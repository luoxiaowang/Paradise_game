# Paradise Game 设计方案

日期：2026-10-22

## 已确认的目标

项目路径：`/Users/luoxiao/Desktop/code/Paradise_game`。
产品是 macOS 小游戏集合，第一款游戏为小霸王 Tank 1990，后续可以添加其他游戏。支持电脑键盘操作、单人、本地双人、自定义按键和声音。不得擅自改编游戏规则、关卡、画面或音效；不得自动 Git commit。

## 实现选择

采用 Swift 原生 macOS 应用外壳与成熟 NES/FC 模拟核心，通过运行固定版本的 Tank 1990 ROM 保留游戏内容。优先评估 Nestopia libretro 核心，锁定实际使用的源码版本，并随交付保留相关许可证、来源和构建说明。第一期针对当前 Apple Silicon Mac 构建；未验证的平台不宣称支持。

不采用凭视频或记忆手写 Tank 1990 的方式，也不以网页近似复刻代替原版。模拟核心也需要进行输入、帧速和音频验证，选型本身不能证明完全一致。

## 产品与模块边界

- 游戏大厅：中文界面，首期只有 Tank 1990 游戏卡片，支持进入游戏、打开设置、返回大厅。
- 游戏目录：每款游戏拥有稳定 ID、名称、运行器类型、资源引用和默认按键配置。资源缺失时展示明确状态，不伪装可运行。
- 运行器接口：加载、启动、暂停、恢复、重置、停止、输入、视频帧和音频输出。第一期实现 NES 运行器，未来其他类型游戏可实现相同生命周期接口。
- 游戏资源：与应用通用逻辑分离。使用固定 ROM 的 SHA-256、文件大小和必要头部信息记录验收版本；不把文件名当作版本证明。
- 输入服务：按玩家映射 FC 方向键、A、B、Start、Select；支持重设、恢复默认、配置持久化，以及同键冲突提示。窗口失焦或返回大厅时释放全部按键，避免持续移动或射击。
- 显示服务：保持原始像素画面和比例，默认整数倍缩放、黑边；支持窗口和全屏，不添加滤镜或重绘素材。
- 音频服务：输出模拟核心产生的声音，提供音量和静音，不以合成替代音效；暂停和退出时清理缓冲。

第一期不实现插件商店、联网对战、账号、排行榜或云同步。扩展点采用应用内静态注册，不引入远程执行插件系统。

## 游戏体验

单人和双人使用 ROM 自带模式和菜单，不改写游戏逻辑。双人指同机双人合作。大厅及设置使用中文；游戏内部文字保留 ROM 原样，避免汉化造成与原版不一致。

初始建议按键：玩家一 WASD、J/K；玩家二方向键、逗号/句号。Start 与 Select 分玩家配置。最终默认按键需通过 macOS 实机同时输入验证；键盘硬件的多键冲突不能仅靠软件保证消除，必须记录测试范围。

关闭游戏返回大厅，关闭窗口按 macOS 应用生命周期处理。资源无效、格式不支持或核心加载失败时给出中文错误信息，不崩溃或静默替换游戏。

## 原版基准与当前依赖

用户已明确 Tank 1990，并确认没有 ROM。资源查找与版本核验由开发方承担，不要求用户自行准备。建议基准为烟山软件 Tank 1990 (China)，最终以实际获得资源的哈希、标题和玩法验证结果锁定。

已核对 MAME 官方 nes.xml 的 tank1990 条目：发行方 Yanshan RuanJian、1990、NROM、32 KiB PRG 和 8 KiB CHR。该条目标注 baddump，因此只能作为识别线索，不能当作完美转储或还原一致性的证明。来源：https://raw.githubusercontent.com/mamedev/mame/master/hash/nes.xml 。目前尚未取得或验证 ROM。未获得可核验游戏资源前，不能声称已交付原版游戏或完全还原。

应用支持本地导入 ROM 并复制到应用数据目录，避免依赖原文件长期停留在下载目录。首期只接受本项目确认支持的 NES 游戏资源；新增其他游戏通过注册游戏及对应运行器实现。

## 验收方式

1. 从 Finder 启动构建出的 `.app`，进入大厅及游戏，验证退出再启动。
2. 记录 ROM 哈希、模拟核心版本、macOS 与硬件版本，建立可重复基准。
3. 对照同一 ROM 的可信参考运行结果，检查标题、关卡地图、坦克与子弹、基地、地形、道具、敌方行为、死亡重生、计分和过关流程；不以只玩第一关证明所有关卡一致。
4. 实机验证单人和双人菜单、移动与射击同时输入、改键、冲突提示、重启后的配置保留，以及失焦释放。
5. 验证开场、射击、爆炸等实际音效、音量、静音、暂停与恢复，检查音画同步和长时间运行。
6. 验证无 ROM、无效文件、启动失败及反复进入退出游戏。
7. 用最小测试运行器验证大厅通过统一接口调用游戏，确认新增游戏无需修改 Tank 1990 实现。

交付源代码、可运行 `.app`、构建说明和验证报告。未进行的测试、未确认的差异以及签名/公证状态如实列出，不将编译成功等同于还原验收成功。

## 实施顺序

先建立原生应用和游戏目录/运行器边界，再集成模拟核心与画面和音频输出，随后完成双人输入及设置持久化，最后使用固定 ROM 对照验证并打包。

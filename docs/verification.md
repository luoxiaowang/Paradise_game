日期：2026-10-22 至 2026-10-23。验证对象：`dist/Paradise Game.app` 1.0.0，Apple Silicon arm64，macOS 15.5（24F74），Swift 6.1。

已交付可启动的原生 macOS 游戏集合，包含 Tank 1990。应用以原版 ROM 驱动游戏逻辑、关卡、像素及音频，不是手写玩法复刻。未完成全部关卡、全部 TANK 模式与原始实体卡带的逐项对照，因此不宣称已证明“与用户当年的卡带完全一致”。

## macOS 窗口实测

通过原生应用 UI 操作，已观察以下结果：

- 启动已打包 `.app`，中文游戏大厅显示 1 款游戏及原版画面预览。
- 录入射击键时按回车提示与 Start 冲突，设置页保持打开；改为 L 保存成功。
- 退出整个应用、重新启动，射击键仍为 L；恢复默认后为 J。
- 静音开关可切换并恢复有声状态；音量控制接入 AVAudioPlayerNode。
- 启动游戏显示 TANK A～N 原版菜单，确认后出现 `TANK H 1990` 标题及原版单 / 双人 / 自建关卡菜单。
- 单人进入第一关，玩家一键盘输入可用。
- 明确观察光标切至 `2 PLAYERS` 后进入第一关，观察两辆玩家坦克与两组玩家状态，分别发送双方移动及射击键。
- Esc 暂停出现遮罩；点击返回大厅打开确认框，Esc 取消后游戏仍暂停，没有在弹窗背后恢复。
- 全屏进入与退出、返回大厅确认流程可操作，无崩溃。
- 测试结束恢复默认按键、音量 70%、未静音，应用保留在大厅。

UI 自动化工具不支持一个调用同时按多个普通键；多键同时输入由模型位掩码测试及真实核心双端口输入序列覆盖。不能据此证明用户所有物理键盘组合均无硬件冲突。

## 独立审阅与修复

独立审阅发现 3 项问题，均已修复：
1. 本地事件监视器错误把 nil 恢复成原事件，导致吞键失效：改为直接返回处理结果，并在真实设置窗口回归回车冲突。
2. 确认框状态未纳入输入路由：新增确认状态，弹窗期间透传系统键盘事件，真实窗口回归 Esc 取消仍暂停。
3. 固定 Nestopia 核心加载失败仍有部分分配资源：加载尝试后无论成功失败都进入对应 unload 清理，新增回归测试。

额外完整流程回归发现并修复：返回大厅销毁确认视图时，确认标记可能残留。stop/reset 现在明确清空标记；已重现修复前新一局 Esc 无响应，并在最终构建重复「开局 → 确认返回大厅 → 再开局 → Esc」，确认新一局正常暂停。

## 版本与限制

- ROM SHA-256：`ec453e7e3cc1d49d11d5860ced7f9e1235e2c7d33927bd6073b631754dc08dbb`。
- PRG CRC32 `3b5b221a` / CHR CRC32 `5e49fac7` 与 MAME 的 Tank 1990 (China) 记录一致；该记录标记 baddump，不能等同完美卡带转储证明。
- 固定核心提交：`06a8949e0b3cf60e3a38a374b1426bf40fccb9a0`。
- 未做全部模式和关卡通关、全部道具/计分/AI 逐项对照、实体卡带音画对照或长时间浸泡测试。
- 音频已确认核心输出有效 PCM 且应用 AVAudioEngine 启动成功；未执行外部录音或人工听辨音色验收，也未验证音频设备热切换。
- 失焦暂停已实现；本次自动化未专门跨应用验证所有系统焦点路径。
- 本地导入入口已实现，格式校验与清单测试通过；没有宣称其他 FC 卡带或特殊外设兼容性已验证。
- 应用仅本地 ad-hoc 签名，未 Developer ID 签名或公证；未验证 Intel Mac 和 macOS 13/14。
- 无 Git 自动提交，无公开发布。
